CHECKLIST DE TESTES DO SCRIPT vp
(espelha os testes automáticos de test_vp.sh)

Pré-requisito único: estar na pasta do projeto, num terminal Git Bash.
  cd /c/Users/rodri/Desktop/SO_Project1

Cada teste abaixo é independente e usa sempre a mesma pasta de trabalho
"teste_vp" (criada e apagada de novo a cada teste) e a mesma BD "teste_vp/bd".
Pode correr qualquer teste isolado, sem depender dos anteriores.


Parte 1 - Casos base

[ ] 1.  -p sem diretórios indicados termina com erro (exit 1)
        ./vp -p -f teste_vp/bd; echo "exit=$?"
        esperado: exit=1

[ ] 2.  -v sem base de dados existente termina com erro (exit 1)
        rm -f teste_vp/bd
        ./vp -v -f teste_vp/bd; echo "exit=$?"
        esperado: exit=1

[ ] 3.  -p e -v usados em simultâneo termina com erro (exit 1)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -v -f teste_vp/bd; echo "exit=$?"
        esperado: exit=1

[ ] 4.  Proteger um diretório com sucesso (mensagem "criada com sucesso")
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        esperado: mensagem "... criada com sucesso."

[ ] 5.1.  O ficheiro da base de dados é criado após o -p
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        ls -l teste_vp/bd
        esperado: ficheiro existe

[ ] 5.2.  A base de dados fica sem permissão de escrita (read-only) após o -p
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        stat --format='%a' teste_vp/bd
        esperado: sem bit de escrita (ex. 400; em NTFS/Git Bash pode mostrar 444)

[ ] 7.  Verificação sem alterações reporta tudo como verificado (0 modificados/apagados/novos)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        ./vp -v -f teste_vp/bd
        esperado: "2 verificados | 0 Modificado(s) | 0 Apagado(s) | 0 Novo(s)"

[ ] 8.  Alteração de conteúdo de um ficheiro é detetada ("Conteúdo")
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        echo "conteudo alterado para ser maior" > teste_vp/alvo/a.txt
        ./vp -v -f teste_vp/bd
        esperado: "a.txt foi MODIFICADO (Alteração de ... Conteúdo ...)"

[ ] 9.  Ficheiro apagado é detetado ("foi APAGADO")
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        rm -f teste_vp/alvo/b.txt
        ./vp -v -f teste_vp/bd
        esperado: "b.txt foi APAGADO"

[ ] 10. Ficheiro novo é detetado ("é NOVO")
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        echo "sou novo" > teste_vp/alvo/c.txt
        ./vp -v -f teste_vp/bd
        esperado: "c.txt é NOVO"

[ ] 11. Exclusão de padrões (-e) ignora ficheiros na proteção e na verificação
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        echo "log volátil" > teste_vp/alvo/debug.log
        ./vp -p teste_vp/alvo -e "*.log" -f teste_vp/bd
        ./vp -v -e "*.log" -f teste_vp/bd
        esperado: "debug.log" não aparece em nenhuma das saídas

[ ] 12. Resumo final mostra contagens corretas com múltiplas alterações (modificado + apagado + novo)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        echo "alterado" > teste_vp/alvo/a.txt
        rm -f teste_vp/alvo/b.txt
        echo "novo ficheiro" > teste_vp/alvo/c.txt
        ./vp -v -f teste_vp/bd
        esperado: "0 verificados | 1 Modificado(s) | 1 Apagado(s) | 1 Novo(s)"

[ ] 13. Proteger múltiplos diretórios ao mesmo tempo funciona e é refletido no resumo
        rm -rf teste_vp
        mkdir -p teste_vp/alvo teste_vp/alvo2
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        echo "ficheiro do segundo dir" > teste_vp/alvo2/x.txt
        ./vp -p teste_vp/alvo teste_vp/alvo2 -f teste_vp/bd
        esperado: mensagem final lista os dois diretórios
        ./vp -v -f teste_vp/bd
        esperado: "3 verificados | 0 Modificado(s) | 0 Apagado(s) | 0 Novo(s)"

[ ] 14. Proteção falha corretamente quando a BD não pode ser escrita (não reporta falso sucesso)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/alvo/a.txt/BD; echo "exit=$?"
        esperado: exit=1, SEM "criada com sucesso"
        ls teste_vp/alvo/a.txt/BD 2>&1
        esperado: erro (ficheiro não existe)

[ ] 15. Proteção falha corretamente quando o diretório indicado não existe
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        ./vp -p teste_vp/nao_existe -f teste_vp/bd; echo "exit=$?"
        esperado: exit=1, mensagem "não existe ou não é um diretório"
        ls teste_vp/bd 2>&1
        esperado: erro (BD não foi criada)


Parte 2 - Edge cases

[ ] 16. Alteração apenas de permissões (chmod) é detetada ("Permissões")
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        chmod 600 teste_vp/alvo/a.txt
        ./vp -v -f teste_vp/bd
        esperado: "a.txt foi MODIFICADO (Alteração de ... Permissões ...)"
        (pode não funcionar em NTFS/Git Bash — ver nota final)

[ ] 17. Alteração apenas da data de modificação (touch, sem mudar conteúdo) é detetada
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        touch -d "@$(( $(date +%s) + 86400 ))" teste_vp/alvo/a.txt
        ./vp -v -f teste_vp/bd
        esperado: "a.txt foi MODIFICADO (Alteração de ... Data de Modificação ...)"

[ ] 18. Conteúdo alterado mantendo o mesmo tamanho é detetado (deteção pelo hash, não pelo tamanho)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        printf 'AAAAAAAAAA' > teste_vp/alvo/a.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        printf 'BBBBBBBBBB' > teste_vp/alvo/a.txt
        ./vp -v -f teste_vp/bd
        esperado: "a.txt foi MODIFICADO (Alteração de Conteúdo)" (tamanho igual)

[ ] 19. -v sem -e herda o padrão de exclusão guardado na BD (definido no -p)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "log volátil" > teste_vp/alvo/debug.log
        ./vp -p teste_vp/alvo -e "*.log" -f teste_vp/bd
        ./vp -v -f teste_vp/bd
        esperado: "debug.log" não aparece (herdou a exclusão guardada na BD)

[ ] 20. -v com -e diferente do usado no -p substitui a exclusão guardada
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "log volátil" > teste_vp/alvo/debug.log
        ./vp -p teste_vp/alvo -e "*.log" -f teste_vp/bd
        ./vp -v -e "*.txt" -f teste_vp/bd
        esperado: "debug.log é NOVO" (exclusão passou a ser *.txt)

[ ] 21. Exclusão de padrão (-e) aplica-se também a ficheiros em subdiretórios aninhados
        rm -rf teste_vp
        mkdir -p teste_vp/alvo/sub
        echo "log aninhado" > teste_vp/alvo/sub/nested.log
        ./vp -p teste_vp/alvo -e "*.log" -f teste_vp/bd
        ./vp -v -e "*.log" -f teste_vp/bd
        esperado: "nested.log" não aparece em nenhuma das saídas

[ ] 22. -f sem valor a seguir termina com erro (não consome a próxima flag por engano)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        ./vp -p teste_vp/alvo -f; echo "exit=$?"
        esperado: exit=1, mensagem "requer um nome de ficheiro"

[ ] 23. -e sem valor a seguir termina com erro
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        ./vp -p teste_vp/alvo -f teste_vp/bd -e; echo "exit=$?"
        esperado: exit=1, mensagem "requer um padrão"

[ ] 24. Switch desconhecido (ex. -x) termina com erro e mostra mensagem clara
        ./vp -x; echo "exit=$?"
        esperado: exit=1, mensagem "Switch inválido"

[ ] 25. Flags podem aparecer depois dos argumentos posicionais (ex. "vp dir -p -f db")
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        ./vp teste_vp/alvo -p -f teste_vp/bd
        esperado: "criada com sucesso"

[ ] 26. Sem -p e sem -v, com diretório posicional dado: comporta-se como -v e ignora o diretório
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        ./vp teste_vp/alvo -f teste_vp/bd
        esperado: "2 verificados | 0 Modificado(s) | 0 Apagado(s) | 0 Novo(s)"

[ ] 27. Exit code de sucesso é 0 tanto na proteção como na verificação
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd; echo "exit=$?"
        ./vp -v -f teste_vp/bd; echo "exit=$?"
        esperado: exit=0 em ambos

[ ] 28. Nomes de ficheiros com espaços são tratados corretamente
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo" > "teste_vp/alvo/com espaco.txt"
        ./vp -p teste_vp/alvo -f teste_vp/bd
        echo "alterado" > "teste_vp/alvo/com espaco.txt"
        ./vp -v -f teste_vp/bd
        esperado: "com espaco.txt foi MODIFICADO"



[ ] 29. Proteger/verificar um diretório vazio (0 ficheiros) funciona sem erros
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        ./vp -p teste_vp/alvo -f teste_vp/bd
        esperado: "Ficheiros processados: 0"
        ./vp -v -f teste_vp/bd
        esperado: "0 verificados | 0 Modificado(s) | 0 Apagado(s) | 0 Novo(s)"

[ ] 30. Subdiretórios aninhados (vários níveis) são percorridos recursivamente
        rm -rf teste_vp
        mkdir -p teste_vp/alvo/sub/subsub
        echo "ficheiro aninhado" > teste_vp/alvo/sub/subsub/deep.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        ./vp -v -f teste_vp/bd
        esperado: " verificados | 0 Modificado(s) | 0 Apagado(s) | 0 Novo(s)"
        echo "alterado" > teste_vp/alvo/sub/subsub/deep.txt
        ./vp -v -f teste_vp/bd
        esperado: "deep.txt foi MODIFICADO"

[ ] 31. Reproteger substitui uma BD anterior só de leitura, sem ser preciso apagá-la à mão
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        echo "outro ficheiro" > teste_vp/alvo/b.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        ls -l teste_vp/bd
        echo "ficheiro extra" > teste_vp/alvo/extra.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        esperado: "criada com sucesso" (sem apagar a BD manualmente)
        ./vp -v -f teste_vp/bd
        esperado: "3 verificados | 0 Modificado(s) | 0 Apagado(s) | 0 Novo(s)"

[ ] 32. -f com diretório-pai inexistente no caminho termina com erro (não só quando é um ficheiro a bloquear)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        ./vp -p teste_vp/alvo -f teste_vp/nao_existe/bd; echo "exit=$?"
        esperado: exit=1, SEM "criada com sucesso"

[ ] 33. Proteger um diretório que contém a própria BD causa auto-modificação na verificação seguinte
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo" > teste_vp/alvo/a.txt
        ./vp -p teste_vp/alvo -f teste_vp/alvo/db_interna
        ./vp -v -f teste_vp/alvo/db_interna
        esperado: "db_interna foi MODIFICADO (Alteração de ... Permissões ...)"

[ ] 34. -s emite um alerta via logger quando é detetada uma alteração
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        ./vp -p teste_vp/alvo -f teste_vp/bd
        echo "alterado" > teste_vp/alvo/a.txt
        ./vp -v -s -f teste_vp/bd
        verificar alerta: journalctl -t vp --since "-1 min"   (ou o syslog do sistema)
        esperado: entrada de log referindo "a.txt foi MODIFICADO"
        (em Git Bash/Windows pode não existir "logger" — confirmar apenas que o comando corre sem erro)

[ ] 35. Ficheiro sem permissão de leitura é omitido silenciosamente da BD (sem aviso ao utilizador)
        rm -rf teste_vp
        mkdir -p teste_vp/alvo
        echo "conteudo original" > teste_vp/alvo/a.txt
        chmod 000 teste_vp/alvo/a.txt
        cat teste_vp/alvo/a.txt > /dev/null 2>&1; echo "leitura bloqueada? exit=$?"
        (se exit != 0, a leitura está mesmo bloqueada e o teste é válido)
        ./vp -p teste_vp/alvo -f teste_vp/bd
        grep "a.txt" teste_vp/bd
        esperado: grep não encontra nada, e sem mensagem de erro no output do -p
        chmod 644 teste_vp/alvo/a.txt


Nota: os testes 16 e 35podemser saltados automaticamente em sistemas de
ficheiros Windows/NTFS via Git Bash, onde chmod não restringe realmente
permissões de escrita/leitura. O mesmo se aplica ao teste 29 se o sistema
de ficheiros não suportar symlinks.

Limpeza final (depois de todos os testes):
  rm -rf teste_vp
